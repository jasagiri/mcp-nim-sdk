## この確認で見つけて直した不具合

- HTTP サーバーが `initialize` の状態をプロセスに 1 つしか持たず、2 人目の旧版クライアントを拒否した。
- HTTP クライアントが、エラー応答に付いたセッション ID を採用し、プレースホルダの id で返されたエラーを
  自分のリクエストと結び付けられなかった (Python 1.30.0 のサーバーで発覚)。
- 旧版までしか話さないビルドが新版の探りに `-32022` を返すと、両対応のクライアントは `initialize` に
  戻らない。未知のメソッドとして返すように設計を改めた (この確認の前に仕様から気付いて修正。
  実際の相手で成立を確かめた)。
