# 公開の前に成り立つべきこと

この SDK の本線 (日付版のコア) を push し、版ごとのタグを付け替える前に、成り立っていなければならない主張と、その根拠の台帳。

- `release.json` — 台帳。主張ごとに、支持する証拠と否定する証拠を書く。
- `release.md` — 台帳を判定した結果。`assurance check docs/assurance/release.json > docs/assurance/release.md` で作り直す (`foundation/nim-assurance`)。
- 判定は四値である: 成り立つ / 成り立たない / 証拠が食い違っている / 誰も確かめていない。必須の主張がすべて「成り立つ」になるまで、公開できない。

公式拡張 (`mcp-2026-07-28-ext`) と下書き (`mcp-draft`) の主張は、まだここに無い。

## 2026-10-13 の状態

26 の主張 (うち必須 24) のうち、成り立つのは 16、成り立たないのは 1、証拠が食い違っているのは 2、誰も確かめていないのは 7 (うち必須 6)。**公開できない。**

成り立たない 1 つ:

- OPS-01 — HTTP サーバーは、要求を送り終えない相手を時間で切らない。README は前段にタイムアウトを持つリバースプロキシを置くよう求めているが、SDK だけでは成り立たない。Nim 2.2.12 の `asynchttpserver` にも `readTimeout` は無い。

2026-10-08 から変わったもの:

- DEP-01 (nimble の下限を `nim >= 2.2.12` に上げた。`base64.decode` の欠陥 nim-lang/Nim#25530 の修正は v2.2.10 以降) と DEP-03 (Nim 2.2.12 を既知の欠陥の一覧と突き合わせた。一覧にあるのは Nim の 1 件だけである)。
- VER-01b、VER-02、IOP-01b、CNF-01b — 2026-10-12 の確認のあとソースとテストが変わったので、2026-10-13 に、5 版の通し、版ごとのコミットの展開、相互接続、適合性テストを取り直した ([release-check-2026-10-13.md](../quality/release-check-2026-10-13.md))。測ったコミットと、この台帳を含むコミットの差は `docs/quality/` と `docs/assurance/` のファイルだけである。**ソースかテストが変わったら、この 4 つは取り直す。**
- SPEC-01 — 「成り立つ」から「証拠が食い違っている」に変わった (下)。

食い違っている 2 つは SEC-01 と SPEC-01 である。SEC-01: 2026-10-06 のレビューの指摘は再現するテストを書いて直したが、指摘の番号とテストを結ぶ表が無く、Tasks の上限の無い 4 か所は利用者の判断待ちで残っている。

誰も確かめていないもの: 変異検査の測り直し (REV-01、REV-01b。テスティングの見直しのあとに行う)、ファジングの入口の一覧の見直し (INP-02) とレビューを実装者以外が行うこと (SEC-02。人の目が要る)、INP-03 と INP-04 (手段がまだ無い。libFuzzer につなぐ手順は未整備)、下流の 3 パッケージのコンパイル (DOWN-01、必須ではない)。

SPEC-01: 宣言した仕様 ID のすべてに、対応表の指すテストがある (`nimble specCoverage` が 469/469)。一方、テストを E / I / 足場に分けると、469 のうち 48 の ID には外部仕様テストが 1 本も結ばれていない ([test-classification.md](../quality/test-classification.md))。結ばれているのは内部のモジュールを直接呼ぶテストで、その呼び口を公開の入口へ移すか、仕様の側を内部の規則として書き直すかは決まっていない。

## 証拠を足すとき

- 証拠は、主張を支持するか否定するかを書く。確かめた日と、確かめ方を `ref` に書く。
- ファイルを指せる証拠は `file` に書く。台帳を読み込むとき、そのファイルが無ければエラーになる。
- **確かめていないことを、支持する証拠として書かない。** 文書に「そうなっている」と書いてあることは、そうなっていることの証拠ではない。
- 食い違う証拠は、どちらも残す。
