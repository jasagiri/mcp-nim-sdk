# 公開の前に成り立つべきこと

この SDK の本線 (日付版のコア) を push し、版ごとのタグを付け替える前に、成り立っていなければならない主張と、その根拠の台帳。

- `release.json` — 台帳。主張ごとに、支持する証拠と否定する証拠を書く。
- `release.md` — 台帳を判定した結果。`assurance check docs/assurance/release.json > docs/assurance/release.md` で作り直す (`foundation/nim-assurance`)。
- 判定は四値である: 成り立つ / 成り立たない / 証拠が食い違っている / 誰も確かめていない。必須の主張がすべて「成り立つ」になるまで、公開できない。

公式拡張 (`mcp-2026-07-28-ext`) と下書き (`mcp-draft`) の主張は、まだここに無い。

## 2026-10-12 の状態

26 の主張 (うち必須 24) のうち、成り立つのは 10、成り立たないのは 1、証拠が食い違っているのは 1、誰も確かめていないのは 14 (うち必須 13)。**公開できない。**

成り立たない 1 つ:

- OPS-01 — HTTP サーバーは、要求を送り終えない相手を時間で切らない。README は前段にタイムアウトを持つリバースプロキシを置くよう求めているが、SDK だけでは成り立たない。Nim 2.2.12 の `asynchttpserver` にも `readTimeout` は無い。

2026-10-08 から変わったもの: DEP-01 (nimble の下限を `nim >= 2.2.12` に上げた。`base64.decode` の欠陥 nim-lang/Nim#25530 の修正は v2.2.10 以降) と DEP-03 (Nim 2.2.12 を既知の欠陥の一覧と突き合わせた。一覧にあるのは Nim の 1 件だけである)。

食い違っている 1 つは SEC-01 である。2026-10-06 のレビューの指摘は再現するテストを書いて直したが、指摘の番号とテストを結ぶ表が無く、Tasks の上限の無い 4 か所は利用者の判断待ちで残っている。

誰も確かめていないものの大半は、公開するコミットでの測り直しである (5 版の通し VER-01b、タグの展開 VER-02、相互接続 IOP-01b、適合性テスト CNF-01b、変異検査の測り直し REV-01b)。測定用の機体が空いてから行う。残りは人の目が要る: ファジングの入口の一覧の見直し (INP-02)、レビューを実装者以外が行うこと (SEC-02)。INP-03 と INP-04 は手段がまだ無い (libFuzzer につなぐ手順は未整備)。

## 証拠を足すとき

- 証拠は、主張を支持するか否定するかを書く。確かめた日と、確かめ方を `ref` に書く。
- ファイルを指せる証拠は `file` に書く。台帳を読み込むとき、そのファイルが無ければエラーになる。
- **確かめていないことを、支持する証拠として書かない。** 文書に「そうなっている」と書いてあることは、そうなっていることの証拠ではない。
- 食い違う証拠は、どちらも残す。
